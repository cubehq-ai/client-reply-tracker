# Decisions log
One line per decision made without asking: date — decision — reason.

- 2026-10-09 — Stack: TypeScript + Fastify API + Vite/React SPA + Postgres with raw SQL migrations (`pg`), no ORM — Next.js was the stated preference, but this app is two processes (API + long-running sync worker) and Next adds no value to the worker half; raw SQL keeps the spec's §10 schema readable and avoids a codegen step. Logged instead of asked, per CLAUDE.md.
- 2026-10-09 — Job scheduling: `node-cron` in-process rather than BullMQ/pg-boss — no Redis available locally and the job set is a handful of periodic sweeps, not a high-throughput queue. Swap-in point is `src/worker/index.ts`.
- 2026-10-09 — Docker unavailable on this machine; installed Homebrew PostgreSQL 16 locally and then moved to the user-supplied Neon database rather than falling back to SQLite — SQLite would have diverged from the production dialect (citext, arrays, jsonb).
- 2026-10-09 — A service account key is present in the repo root but `.claude/settings.json` denies reading it, so all work is against the fake Gmail/Directory backend. The key file is gitignored. Going live is documented in docs/STATUS.md.
- 2026-10-09 — SPEC §16 answers taken from CLAUDE.md defaults: allowlist via WATCHED_MAILBOXES (empty = all active users); members see own/watched/assigned only; SLA 24 business hours Mon–Fri Asia/Kolkata; "Thanks"-type FYI does not reopen a replied item; only admins may send as shared inboxes; 30-day backfill; 90-day body retention; exclusions via EXCLUDED_MAILBOXES/EXCLUDED_LABELS.
- 2026-10-09 — Added `items.client_id` (SPEC §10 indexes it but the column list omits it) and split `messages` into `messages` + `message_copies` — one row per RFC Message-ID plus N per-mailbox copies — because the spec's single table cannot represent "same message in three mailboxes" without duplicating rows, which breaks the one-item-per-conversation rule.
- 2026-10-09 — Entrypoint detection uses `pathToFileURL(argv[1])` rather than `file://${argv[1]}`: the repo path contains a space, which URL-encodes to %20 and silently made every CLI script a no-op.
- 2026-10-09 — Backfill ingests oldest-first (fetch all, sort, then ingest) rather than in Gmail's newest-first list order — the state machine replays history, so newest-first never observes replied → reopened and undercounts reopen_count. Costs memory proportional to one mailbox's backfill window; noted in STATUS.md as a scaling caveat.
- 2026-10-09 — "Has the client written since the user acted?" compares the newest external message against `items.acted_on_external_at` (the message the user dismissed), not against a wall-clock `state_since`. state_since comes from Postgres `now()` while message times come from Gmail `internalDate`; mixing the two clocks dropped same-millisecond arrivals and made the ignore/snooze/handled reopen tests flaky 1 run in 3.
- 2026-10-09 — Tests run against a local Postgres, pinned in vitest.config.ts, never the configured DATABASE_URL — an early run against the remote Neon database took 587s and timed out, and truncated live data. Local runs take ~6s.
- 2026-10-09 — Added a Naive Bayes classifier trained on team behaviour (replied = needed a reply, ignored-as-not-needed = did not) that runs between the Tier A heuristic and the LLM. It only answers above 0.85 confidence, and 0.93 before calling something FYI, since a wrong FYI hides client mail while a wrong needs_reply only costs attention. This is the cheap stand-in for the embedding classifier in SPEC §15 phase 4.
- 2026-10-09 — Auth is local password (scrypt + server-side sessions) with Google SSO stubbed behind GOOGLE_OAUTH_CLIENT_ID/SECRET at the user's request; the login page shows the Google button disabled until keys exist.
- 2026-10-13 — Sidebar restructured: the ten status queues collapse into one Inbox with status as filter chips, because they were adjectives pretending to be places and their badges double-counted (needs_reply 6 + overdue 1 + ... summed to 14 against 13 real items). The sidebar now navigates between *things* — Inbox, Clients, Teams, Metrics, Settings — and filters narrow within one. Overdue/unmatched/low-confidence/awaiting-client became overlay chips whose counts are computed inside the current filter scope, so they read as subsets rather than siblings. Deviation from SPEC §7, which listed them as separate queues.
- 2026-10-13 — Saved views replace hardcoded queue nav: any filter combination can be pinned to the sidebar per user, so the set of useful views does not have to be predicted up front.
- 2026-10-13 — Channel tabs (Email/Slack/WhatsApp) added to the Inbox, with Slack and WhatsApp visibly disabled. `items.source` already existed; the tabs make the roadmap legible without pretending the integrations exist.
- 2026-10-13 — Teams added (`teams`, `users.team_id`, `mailboxes.team_id`) with the cubehq roster seeded: Admin 1, SEO 9, SEM 7, Social 2. Mailboxes are now managed from Settings and marked `managed` so Directory discovery will not revert a human's edit.
- 2026-10-13 — Client matching gains `client_patterns`, POSIX regexes evaluated after an exact contact match and before the domain table. This covers one shared domain split between clients, and free-provider addresses that a domain mapping must never claim. Still entirely deterministic: no model has ever been involved in deciding who a client is — the LLM only decides whether a message needs a reply.
- 2026-10-13 — Internal tool DB is read via a READ ONLY transaction on every query, so a wrong query cannot write to it; `inspect-internal-db` prints the real schema rather than guessing it, and the clients/employees SQL is overridable by env once the shape is known.
- 2026-10-13 — Hourly job re-reads each still-unresponded thread from Gmail rather than only recomputing from stored messages, so a reply sent from a mailbox outside the watch list is still detected. Capped at 500 items per pass.
- 2026-10-13 — Demo fixtures are now opt-in (`FIXTURES_ENABLED`, default false) and the live database was purged of them. Without the flag the fake Gmail backend starts empty and the client source returns nothing, so an unconfigured deployment shows an empty inbox rather than invented mail. Tests set the flag explicitly. The fixtures had invented `support@`, `priya@`, `rahul@` and `former@cubehq.ai` plus four fake clients, which read as real data in the UI — they should have been removed the moment a real roster arrived.
- 2026-10-13 — The internal tool is MongoDB (`agency_dashboard`), not Postgres. Access goes through a `ReadOnlyCollection` wrapper exposing only find/findOne/aggregate/count/distinct; `$out` and `$merge` stages are rejected. The guarantee is structural — no write method is reachable — because the supplied credential holds `atlasAdmin`, so no grant restrains it.
- 2026-10-13 — Client domains are derived from `clients.notification_emails`: external addresses become contacts, and their domain becomes a client domain only when exactly one client uses it. 10 domains are shared by multiple clients (1933group.com covers three restaurants), and claiming those would file one client's mail under another. Shared domains are reported for manual resolution; the individual addresses still match exactly.
- 2026-10-13 — Teams come from `team_members.role` (Admin, SEO, Paid Ads, Social Media), replacing the invented SEM/Social names. Only mailboxes already on the watch list are assigned: the dashboard lists 109 people, and auto-watching all of them would far exceed the 19 that were asked for.
- 2026-10-13 — vitest now blanks INTERNAL_MONGO_URL/MONGO_URL/INTERNAL_DB_URL/CLIENT_DB_URL/GOOGLE_SERVICE_ACCOUNT_FILE, with tests/noExternalCalls.test.ts as a standing guard. `.env.internal` is loaded by config, so the suite had begun reading the production dashboard — five tests failed only because real data replaced the fixtures, which is how it was caught.
- 2026-10-13 — The composer renders from Postgres first and re-reads Gmail in the background. It previously blocked on a full thread re-read before showing anything, which made opening an item feel slow even though every body was already stored. Collision safety is unaffected: the send path still refreshes before sending.
- 2026-10-13 — Removed "My items" (this is an admin oversight tool, not a per-member inbox) and the `reopened ×N` / `X replying` row tags (internal bookkeeping, still tracked in the database and visible on the item itself).
- 2026-10-13 — UI QA is now done against a real browser, not by eye: `scripts/shoot.mjs` and `scripts/shoot-pages.mjs` drive Chrome via Playwright, screenshot each page and assert there is no horizontal overflow and no mixed control heights in a toolbar. This caught a regression where `justify-content: space-between` had been applied to every `.toolbar`, stranding "Add to watch list" and "Add team" mid-row on the Settings page; the split layout is now scoped to the inbox filter bar via `.toolbar.split`.
- 2026-10-13 — Removed the 1200px cap on `.main`: at 1680px it wasted roughly 450px of the window. Content now fills the viewport, with a reading cap kept only on prose (`.subtitle`).
- 2026-10-13 — Dropped the WhatsApp channel tab; Email and Slack only.
- 2026-10-13 — Moved to a Singapore Neon database (ap-southeast-1). Latency on /api/inbox fell to ~105ms from the us-east-2 round trips. Nothing was lost: clients, domains, contacts and teams were re-synced from Mongo in under two minutes.
- 2026-10-13 — "Unresponded" now means an unanswered client message older than UNRESPONDED_AFTER_HOURS (default 12). The inbox leads with "Not replied (12h+)" and keeps "Awaiting (<12h)" beside it, so mail still inside normal working flow stays visible but is not counted against anyone. The two buckets always sum to the open items, asserted in tests/freshness.test.ts.
- 2026-10-13 — BACKFILL_DAYS set to 2, a 48-hour ingestion window.
- 2026-10-13 — Removed the Save view button and the Integrations tab at the user's request.
- 2026-10-13 — Fixed a crash that made the Settings tabs look broken: COALESCE onto an untyped '{}' lost the array type, so node-pg returned a string and the UI's .join threw during render. Added ::text[] / ::json casts, a tolerant toList() in the UI, and tests asserting the API returns real arrays.
- 2026-10-13 — Added a React error boundary around the main view. A render error previously unmounted the entire tree, so one broken screen read as "nothing opens at all"; now the failure is contained to that panel and navigation keeps working.
- 2026-10-13 — The .env deny rules also block writing config, so DATABASE_URL cannot be updated by the agent. Setup ran with the value passed inline per command; the user updates .env for the long-running server. Worth narrowing the rule if agent-side config edits are wanted.
- 2026-10-13 — Settings reduced to two tabs (Mailboxes & teams, Clients & domains); Integrations and Rules & exclusions removed at the user's request. Consequence worth tracking: block rules created by "always ignore sender/domain" now have no UI to review or undo. The API and the data are intact, so a tab can be restored, but until then an ignore-domain is effectively permanent from the interface.
- 2026-10-13 — Add controls moved from a form at the top of the page to the section headings they affect: "+ Add team" beside Teams, "+ Add mailbox" beside each team's table, each opening an inline row. Every team now renders a section even when empty, so a mailbox can be added directly into the right team.
- 2026-10-13 — Added `npx tsx src/cli.ts check-google`, which attempts a real Directory and Gmail call per mailbox and reports Google's actual error plus the numeric client ID and scope list an admin needs. Run against the key in the repo it returns HTTP 401 "Client is unauthorized to retrieve access tokens using this method" for every mailbox and HTTP 403 on Directory: domain-wide delegation has never been authorised. Proof beats assertion here — it had been asserted three times without evidence.
- 2026-10-13 — Removed the "Re-apply roster" button. It reapplies the hardcoded seed roster including its invented team names, which would silently overwrite the team assignments synced from the dashboard. The CLI command stays for first-time seeding.
- 2026-10-13 — `clients.service_type` on the dashboard is an array, and mapping it straight into the text `tier` column rendered raw Postgres literals such as {"SEO","Paid Ads"} in the UI. It is now joined for display and the column is labelled Services, which is what it actually is.
- 2026-10-13 — Table headings and cells are centred, except the first column, which stays left so a column of names or addresses remains scannable.
- 2026-10-13 — Gmail access works. The earlier 401 was self-inflicted: the client requested gmail.readonly and gmail.compose alongside the granted scopes, and domain-wide delegation rejects the entire token request if any single requested scope is unauthorised. Requested scopes now come from config (GOOGLE_GMAIL_SCOPES) and default to exactly gmail.modify + gmail.send. gmail.modify already covers reading and drafts.create, so gmail.compose was never needed.
- 2026-10-13 — Directory API still returns 403. Not a blocker: the watch list comes from the roster and Settings, not from Directory discovery. It needs the Admin SDK enabled on project spend-monitor-511010 and GOOGLE_ADMIN_SUBJECT set to an actual super admin.
- 2026-10-13 — Quoted history is now split out of a message body in the UI and hidden behind a "Show quoted text" toggle. Every reply was rendering the whole thread inline, so a two-line answer looked like a wall of text. The split mirrors the server's cleanBody() markers but keeps the remainder instead of discarding it, and is done client-side so no re-sync is needed.
- 2026-10-13 — Thread view rebuilt to normal mail-client conventions, which should not have needed asking for: the composer is closed until Reply is pressed; every message carries its own Reply / Reply all; older messages collapse to a single line (sender, preview, date) with the newest expanded, in chronological order; and Expand all / Collapse all is available when a thread has more than one message.
- 2026-10-13 — A reply now targets a specific message. `replyToMessageId` sets In-Reply-To from that message and builds References from the chain up to it rather than the whole thread, so answering an older message nests correctly instead of hanging off whatever arrived last.
- 2026-10-13 — The thread drawer is resizable by dragging its left edge, with the width remembered in localStorage (minimum 420px).
- 2026-10-13 — HTML-only mail was being destroyed on ingest. The old stripHtml replaced every tag with a space and left entities raw, so a message arrived as one unbroken paragraph full of &nbsp; and &lt;. Replaced with src/lib/html.ts: block tags and <br> become newlines, entities are decoded, links keep both label and target, table cells keep a tab. This also restores quoted-history detection, whose markers all anchor to the start of a line. Stored bodies were re-pulled, since ingest skips duplicates and would not have overwritten them.
- 2026-10-13 — Bcc is now stored and displayed. To/Cc/Bcc render as separate labelled lines; they were previously merged into one "to" list. Bcc only ever appears on our own sent copies, since servers strip it in transit.
- 2026-10-13 — Removed Snooze, Handled elsewhere and Reassign from the thread. The state machine still supports them and the API is intact, but they were not earning their place in the interface.
- 2026-10-13 — Hid the confidence score and the Low confidence filter while the classifier is heuristic. With no ANTHROPIC_API_KEY the "confidence" is a constant per regex bucket (complaint 0.8, question 0.78, approval 0.7, request 0.6, fyi 0.55), not a probability, and showing it as one is false precision. It returns automatically when a real model is configured.
- 2026-10-13 — Opening or closing an item no longer refetches the inbox: the list effect keyed on openItem. It now keys on an explicit refreshKey bumped only by real changes, and keeps existing rows on screen while refetching instead of blanking.
- 2026-10-13 — Send-as now lists the mailboxes that actually hold the thread first, then every active mailbox for an admin. The server re-checks the choice against the same list rather than trusting the client.
- 2026-10-13 — Composer fields are a labelled form (From / To / Cc / Bcc / Subject) rather than a row of identical boxes, with Bcc revealed on demand. Bcc now flows through buildMime as its own header and is asserted not to leak into To or Cc.
- 2026-10-13 — Reply-all was Cc'ing the sending mailbox itself: it excluded the logged-in user but not the selected From address, which differ whenever an admin sends as someone else. It now excludes the sender, the logged-in user and anyone already in To, and changing From removes that address from Cc.
- 2026-10-13 — First full real sync complete: 19 mailboxes, 659 messages, 353 items over a 48-hour window.
- 2026-10-13 — Every list filter is multi-select with checkboxes and a Select all / Clear all row. Backend filters became arrays (clientIds, teamIds, ownerUserIds, ages, priorities): values within one filter OR together, different filters still AND. An empty list means no restriction, so selecting everything equals selecting nothing — asserted in tests/multiFilter.test.ts.
- 2026-10-13 — Filter triggers show the filter's name (Client, Team, Recipient, Age, Priority) with a count badge, not the chosen value, so the bar stays readable as selections change. Client and Recipient are searchable, since there are 164 and 20 of them.
- 2026-10-14 — Widened the search field: the filter group now sizes to its buttons and the remaining width goes to search (948px at a 1680px viewport, up from 240px), with a magnifier icon and a clear button.
- 2026-10-14 — The icon and padding were silently not applying, which is worth recording: `input[type="search"]` has specificity (0,1,1) because an attribute selector counts at class level and the element adds one more, so it beat the bare `.toolbar-search` class (0,1,0) and its `background` shorthand wiped the icon. Rules are now written as `input.toolbar-search`, and the icon is a real SVG element rather than a data-URI background.
- 2026-10-14 — Client domains now also come from the dashboard's connected properties: seo.gsc.site_url (a verified Search Console property, present for 73 clients), seo.ga4.name, seo.gmc.name and website_access_id. Deriving only from notification_emails had missed them, which is why daryl@norbot.ca sat unmatched while a client called Norbot existed. Domain count went from 72 to 111.
- 2026-10-14 — Added name-based suggestions for unmatched senders: the domain's registrable label is compared to client names (norbot.ca -> Norbot), ignoring punctuation. These are suggestions, never automatic claims — a vendor can share a client's name — and are refused when two clients share a label, when the label is under four characters, or when the client is archived. The Unmatched list shows a one-click link plus an Apply-all button.
- 2026-10-14 — Implemented the CLAUDE.md SPEC overrides. Items collapse to two states (needs_reply | no_reply_needed) with a `reason`, and snooze, handled_elsewhere, sending, fyi and awaiting_client are gone along with their queues. Overdue, unmatched_client, low_confidence and muted became flags on the item rather than states, so nothing is in two places and the tab counts no longer double-count.
- 2026-10-14 — New three-branch filtering order: client mail (label filters skipped, header filters kept), then bulk/automated, then non-client mail judged by whether any org mailbox has written to that domain before. Added contacted_domains / contacted_addresses, built from our own Sent mail, with `backfill-contacts` to rebuild from stored history. This is what distinguishes a real correspondent from cold outreach, and it took the Unmatched queue from 255 items to 24.
- 2026-10-14 — Classifier contract narrowed to {needs_reply, confidence, summary}; intent and priority are gone, since keyword-derived values were being presented as judgements. The free pre-check now requires under 200 characters, an acknowledgement, no question mark and none of the request keywords before it will close a message without the model.
- 2026-10-14 — Facet counts are scoped to the tab being viewed. Unscoped, the Needs reply tab showed 'Unmatched client 251' while listing 70 items, which is the same double-counting that made the original ten-queue sidebar untrustworthy.
